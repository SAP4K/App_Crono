## Verified Code and API Context

- Manifest: Expo `~57.0.32`, Expo Router `~57.0.30`, React Native `0.86.3`, React Native Web `^0.21.2`. Read matching official docs again before implementing platform API usage.
- `src/app/_layout.tsx` imports `Tabs` from the public `expo-router/js-tabs` entry. Its screen options currently select `fade` while active with normal motion, otherwise `none`; the timing duration comes from `motionTokens.routeMs` (180 ms). `sceneLayout` is a stable component wrapper, and the four screens retain stable route identities.
- SDK 57 bundles the relevant navigation implementation inside `expo-router`. There is no installed standalone `@react-navigation/bottom-tabs` package. Derive the interpolator type from the publicly exported `BottomTabNavigationOptions['sceneStyleInterpolator']`; `BottomTabSceneStyleInterpolator` exists internally but is not re-exported. Avoid private imports or adding a separate navigator package.
- Installed `build/react-navigation/bottom-tabs/types.d.ts` exposes `sceneStyleInterpolator({ current: { progress } })`. Progress is negative for a route left of the active index, zero for the active route and positive for one to its right. The interpolator has no viewport/layout argument; obtain width from the existing bounded application layout.
- The bundled `forShift` translates only 50 px and fades. Merely changing `animation` to `shift` does not provide the selected full-width travel. A small typed interpolator can map progress `[-1, 0, 1]` to horizontal offsets `[-width, 0, width]`, retaining opaque content. Keep an enabled navigator animation for attachment/progress and override its scene style; use `none` and zero duration when motion is disabled.
- Bundled `BottomTabView` already animates the previous and focused routes, initializes progress appropriately for direct loads, clips the scene container, and uses the native driver on mobile. Preserve that single animation owner. Do not add another route-progress controller, screen copy, pager, timer loop or per-frame React state.
- Measure the actual existing app viewport, whose `maxWidth` is 480. A browser window width is not necessarily its scene width. Retain safe areas, header, notices and tab placement; unavailable/zero layout must leave the active route usable and centered.
- `NavigationScene` gates native interaction/accessibility with focus. Its web variant uses DOM `inert`, `aria-hidden` and pointer gating while preserving outgoing visual layout. These gates do not own portaled sheets; do not replace them with a route-level MotionScope or broad visibility wrapper.
- `ActiveActivities` and validated notification responses use `router.navigate`; the empty History action uses an actual Expo Router Link. Direction must not be set only inside TabBar's onPress handler. Existing `backBehavior="initialRoute"` and URL/history behavior remain authoritative.
- `tests/e2e/navigationTransitions.spec.ts` currently samples ancestor opacity and contains seven navigation/focus/state journeys. Replace obsolete fade assertions with real horizontal-geometry assertions while retaining the functional assertions. `sheetTransitions.spec.ts` continues to assert vertical sheet/backdrop/panel motion.

Official references checked: [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/), [Expo documentation index](https://docs.expo.dev/llms.txt), [JavaScript tabs](https://docs.expo.dev/router/advanced/tabs.md), and [tab animation customization](https://reactnavigation.org/docs/bottom-tab-navigator/#animations). Upstream navigation docs are conceptual guidance; the installed public SDK-57 entry/types govern imports and compatibility. The separate [React navigation-transition feature](https://docs.expo.dev/router/advanced/navigation-transitions.md) is marked SDK 58+ and is not this visual animation API.
