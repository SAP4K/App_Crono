## Investigation Evidence

- Timer and Planning already wire the shared `DurationPicker` interaction state to both button styling and the press handler. `DurationPicker.tsx` combines per-column busy state and `durationWheel.ts` publishes the centered value before clearing busy. The reported Timer discrepancy needs a reproduction with the user's input and app build. Timer additionally uses focus and preset presentation, and the shared controller accepts scroll updates only after a gesture begins. A missing begin, stale terminal, focus change, or visual disabled-state issue are hypotheses. [Timer source](../../src/app/timer.tsx) · [Controller and presentation bridge](../../src/hooks/useDurationWheel.ts)
- Planning places **Aplică durata** and **Renunță** in adjacent vertical siblings. The primary's margin is above it, the secondary's margin is below it, and their parent sets no gap. The calendar panel already uses a 12-unit action gap. [Duration panel](../../src/components/ScheduleEditorSheet.tsx) · [Calendar panel](../../src/components/ScheduleCalendarPanel.tsx)
- The current Android fling caps its starting speed at the measured release velocity, then uses the native deceleration curve. The app-controlled browser wheel curve starts with its fastest segment. The requested early increase needs a different velocity profile. ScrollView's deceleration rate controls friction, and Android's existing OverScroller has no public interpolator setter. [Release-speed verification](../patches/2026-11-19-11.29.md#verification) · [Browser easing](../../src/hooks/wheelDeceleration.ts) · [React Native ScrollView](https://reactnative.dev/docs/0.86/scrollview#decelerationrate) · [Android 12 OverScroller](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-12.0.0_r1/core/java/android/widget/OverScroller.java)

## Requirements Reconciliation

Authority: The new request defines the action behavior, spacing and motion shape. PR #30 defines the release continuity, exact-row and stop-to-action baseline. Interpret the new motion as a short continuous increase after deliberate manual release or at the start of an app-controlled wheel glide, then a longer progressive slowdown. An increase over several frames is intentional. The first post-release speed still follows the observed release without a jump. While a finger is in contact, the wheel follows it directly.

The web wheel and trackpad driver accelerates, brakes and rebases from the visible offset and compatible speed when retargeted. iOS and browser touch keep platform physics.
