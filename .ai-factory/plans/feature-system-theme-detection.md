## Technical Evidence and Approach

- `src/core/stopwatch.ts` currently uses `ThemeMode = 'light' | 'dark'` for both storage and rendering, seeds `theme: 'light'`, and accepts only manual values in `restoreData`. Introduce pure preference helpers in `src/core/themePreference.ts`: resolved `ThemeMode`, saved `ThemePreference`, default, validation/restoration and effective-mode resolution. Keep core independent of React/native APIs.
- `src/core/backup.ts::readPreferences` independently validates theme for both parsing and serialization. Update it atomically with the stored union; accepting System in startup alone would break exports for the new default.
- `src/context/ThemeContext.tsx` indexes `palettes` with the stored value and calls `Appearance.setColorScheme(mode)`. Keep `useTheme().mode` strictly resolved Light/Dark, with stable palette references. `_layout.tsx` derives StatusBar style from this resolved mode; other components mostly consume colors/cached styles.
- Installed packages are Expo `~57.0.32`, React Native `0.86.3`, React Native Web `^0.21.2`, and Expo SystemUI `~57.0.4`. Read the matching documentation again before API edits if versions change. React Native **0.86** resets a manual override using `Appearance.setColorScheme('unspecified')`; do not copy the newer `'auto'` API from current unversioned docs. Its installed `Appearance.js` refreshes its cached snapshot on reset without explicitly emitting its JS change event. Explicitly reread after resetting before relying on subscriptions.
- Use a small injected appearance synchronizer in `src/hooks/themeAppearance.ts` and a React/platform bridge in `src/hooks/useSystemTheme.ts`. It owns appearance observation/override and foreground refresh only, with cleanup and same-value suppression. It never owns AppData or timers. Native bindings use Appearance; web bindings use the existing React Native Web Appearance observer, which uses `matchMedia` and has **no** `setColorScheme` method. Keep platform calls guarded; no native-only import leaks into web.
- Changing a preference controls the native override. Changing the effective mode controls semantic colors, navigation, root background and status contrast. Avoid reapplying the resolved manual override in System mode. Serialize/coalesce asynchronous native background writes so the latest effective mode wins after rapid changes; discard obsolete queued work on cleanup.
- `src/components/SettingsSheet.tsx` currently has a binary summary and Dark mode switch. Replace only the Appearance controls with existing radio-choice patterns; show System in its summary even when the active palette is Light/Dark. New labels/help belong in `src/i18n/types.ts` and all `ro/en/ru/es/fr/de` catalogs.
- Preserve the current native launch-image limitation: the splash precedes saved preferences and is not part of this feature. No icon/assets/splash redesign or automatic app-scheduled day/night policy is requested.
