# Restore contrast for Studio interactive outlines

**Date:** 2026-11-12 15:31 Europe/Bucharest
**Files:** `src/app/timer.tsx`, `src/app/planning.tsx`, `src/components/ScheduleEditorSheet.tsx`, `tests/e2e/theme.spec.ts`, `README.md`
**Severity:** medium

## Problem

Studio verification found that enabled outlined controls used borders below the plan's 3:1 contrast requirement. Actual browser measurements against the adjacent surface were 1.2736087387004313:1 in Light and 1.5913271247360234:1 in Dark. Quick presets, Planning filters/templates and secondary editor actions shared the affected styles. Existing palette tests passed because they checked the intended interactive token rather than each rendered control's actual token.

## Root Cause

The redesign reused `c.separator`, intended for decorative divisions, in three shared interactive-outline styles. The low-contrast separator is appropriate for visual grouping but does not satisfy the explicit interactive-border requirement. Testing palette constants alone did not establish that components used those constants.

## Solution

Replace only those three `borderColor: c.separator` values with `c.border`. Decorative separators, palette values, state/timing owners, persistence, wheel physics, dependencies and motion behavior are unchanged by this fix.

Register two Light/Dark browser regressions in `tests/e2e/theme.spec.ts`. Each checks 21 enabled controls: four presets (including the selected preset), two filters, two date-sheet actions, eight templates, three editor actions, duration Cancel and dirty-draft Discard. Read actual computed border and adjacent inside/outside colors, assert a visible border and at least 3:1 contrast on both sides, then discard the draft and compare the complete stored data with the original seed. Assertion diagnostics use `[FIX:studio-outline]`. No runtime logging was added, preserving the user's warnings/errors-only preference.

## Prevention

- Reserve decorative separator tokens for non-interactive divisions; use the semantic interactive-border token for outlined controls.
- Check actual rendered computed styles in regressions. Palette-level tests cannot detect an incorrect token at a component call site.
- Exercise shared-style consumers in selected and unselected states, nested panels and dirty-draft confirmation, while verifying stored data is preserved.
- Reproduce a reported failure before editing; retain the same registered assertions for the fresh export. Bind results to source/export/runner hashes and use separate discovery output so test listings cannot replace execution reports.
- Useful further coverage: keyboard-focus ring contrast and physical large-text/contrast checks when deferred native acceptance resumes. Keep those distinct from the completed browser checks.
