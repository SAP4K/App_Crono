# Register every language and independent clock-state restoration combination

**Date:** 2026-11-07 02:39 Europe/Bucharest
**Files:** `tests/language.test.ts`
**Severity:** low

## Problem

Verification found that the language restoration test paused the timer but left the schedule running. The registered suite therefore did not cover restoration of a paused schedule under all six saved languages, including the independent running-timer/paused-schedule and both-paused combinations.

No application failure was reproduced. A separate read-only verification matrix had already passed all 24 combinations, but that temporary probe did not run under `npm test`.

## Root Cause

The original test reused one planning snapshot while changing only the timer status. Its broad running/paused description hid the fact that two independent activity states were not varied independently. Temporary verification evidence was not promoted into the registered regression suite.

## Solution

Replace the single mixed restoration test with 24 named cases: six registered languages × running/paused timer × running/paused schedule. Keep the existing default/validation and literal legacy-fixture tests.

Construct valid snapshots with the public timer and schedule operations. Pause at 2234ms after starting at 1000ms, retaining exactly 8766ms of a 10000ms action. Include a second named action and mixed-script user text. Assert selected statuses, exact remaining milliseconds, deadlines, independent run IDs, the entire restored object, and a second serialize/restore at a later injected time.

The file remains registered by the existing `package.json` test script. No application source, dependencies, schema, native config, context documentation, feature-plan status or browser test was changed.

A temporary coverage-presence check executed the real test file with the TAP reporter and required the 24 explicitly named scenarios. Before the fix it exited 1: none of those explicit matrix case names existed, although the old mixed test passed and covered part of the matrix. After the fix the exact same check exited 0 with 24/24 named scenarios, and all their behavioral assertions passed. This reproduced the durable coverage omission; it is not a claim that runtime restoration failed before the fix. The presence probe was kept outside the repository rather than committed as an implementation-mirroring test.

Validation from the project root, using Windows Node/npm from WSL:

```text
python3 /tmp/crono-language-restoration-coverage.py
node --test --test-reporter=tap tests/language.test.ts
npm test
npm run lint
npm run typecheck
```

The language file passes 26 tests; the full registered Node suite passes 119 tests. Lint, typecheck and whitespace checks passed. SHA-256 comparisons across 120 pre-existing source/test/asset/context/config files confirmed that only `tests/language.test.ts` changed during this fix. Command catalog revision remains `33a77fae797fdd1d3fbb758a78a5ef4c738195f015d7cd42902baaab8ccfc2a1`.

Browser tests and exports were not repeated for this Node-test-only correction. Their preceding successful run covered 162 browser cases and Android/iOS/web exports on unchanged application code. Native-device/accessibility/notification acceptance and independent linguistic review remain pending.

The user's WARN/ERROR-only runtime logging policy is preserved. Named tests and assertions provide case diagnostics; the temporary command check uses `[FIX:language-restoration]`. No routine application logs or debug environment flags were introduced.

## Prevention

- Treat language, timer status and schedule status as independent selectors when checking restoration requirements; enumerate the applicable product.
- Use public state transitions to create coherent saved fixtures, then assert externally expected precision and identities explicitly.
- Promote successful temporary verification probes into files executed by the registered test command before treating coverage work as complete.
- Preserve no-defaulting and literal legacy checks alongside the new state combinations.
- Useful additional coverage: restore a paused schedule after advancing to a later action under each selected language. Keep physical native acceptance separate from Node/browser evidence.
