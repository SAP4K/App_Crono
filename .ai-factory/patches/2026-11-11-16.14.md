# Restore duration-wheel scrolling when animation-frame operations fail

**Date:** 2026-11-11 16:14 (Europe/Bucharest)
**Files:** `src/components/DurationWheel.web.tsx`, `tests/e2e/durationInertia.spec.ts`
**Severity:** medium

## Problem

The verification fault-injection probe threw from `requestAnimationFrame` during browser wheel takeover. The exception escaped and the column still had `overflow: clip` and a translated row container after 1.2 seconds. The manual controller's watchdog released Start, but did not restore the temporary scroll styles. The same shared adapter serves Timer and Planning action durations.

## Root Cause

The visual deceleration controller guarded its own frame scheduling, but wheel setup called the separate compositor-cancellation alignment before entering that guard. This alignment temporarily removed the scroll container and scheduled two frames without protecting either scheduling boundary. Its release also called `cancelAnimationFrame` before restoring styles, so a cancellation exception skipped independent cleanup. Unguarded delayed alignment callbacks could run after their request had been replaced when cancellation failed.

## Solution

- Catch scheduling failure at both alignment frames and release the temporary layout immediately.
- Clear pending ownership before cancellation and restore overflow, transforms and the current offset in `finally`, even if cancellation throws.
- Guard both callbacks against the current alignment identity so obsolete callbacks cannot release a newer alignment.
- Emit a bounded, payload-free `[FIX:wheel-alignment]` warning once per column lifetime. The user's warnings/errors-only logging preference takes precedence over routine input/success logging.
- Register six browser regressions in the existing inertia suite: initial scheduling, nested scheduling and cancellation failure, each in Timer and Planning. Check restored scroll/snap styles, exact selection, enabled controls, another real wheel gesture, unchanged unrelated data and one warning.

## Prevention

- Inject failures through the real browser adapter as well as the pure motion controller; setup can fail before the guarded driver begins.
- Restore temporary UI resources independently from fallible cancellation, and invalidate callback identity before attempting cancellation.
- Exercise both the first scheduling call and a later callback's rescheduling call. A try/catch surrounding only initial scheduling cannot catch exceptions raised later.
- Promote a useful temporary probe into the registered suite and demonstrate failure before changing production code; preserve positive controls and real-input retry assertions.
- Keep validation evidence bound to actual source/export/test manifests. Preserve historical full-suite evidence without treating it as current-source coverage after a corrective change.
- Suggested additional coverage: rapid row-geometry changes during a failed cancellation, followed by delivery of the obsolete callback. Physical Android/iOS tests remain separate from browser/export evidence.
