# Scope blocked-preview feedback to the active alert

**Date:** 2026-11-05 02:17 UTC
**Files:** `src/components/SettingsSheet.tsx`, `tests/e2e/sounds.spec.ts`
**Severity:** low

## Problem

When a live timer alert blocked a sound preview, Settings displayed `O alertă este deja în redare.` The message remained after the alert finished naturally or the user pressed `Oprește sunetul`, even though playback had stopped.

## Root Cause

Settings stored the message text in local state without connecting it to the playback request that caused it. Only another preview attempt, a sound/duration selection, or closing Settings cleared that state. Playback completion and global Stop updated the shared audio controller but left the local message visible.

## Solution

Store the event ID of the live alert that rejected the preview. Derive the message from that ID and the current pending/playing request, excluding previews. Feedback disappears when the request ends, fails, stops, or is replaced. Read the controller's current request after rejection, and retain the existing clearing behavior for Settings close and selection changes.

Added two browser regressions for natural duration completion and explicit Stop. Both first failed at the assertion that the warning should disappear. The exact same checks passed after the fix; they also verify that the completed timer remains unchanged and a later preview succeeds. All seven existing sound scenarios passed afterward. Lint, typecheck, and diff checks passed.

Commands executed with Windows Node.js from WSL:

```bash
node node_modules/@playwright/test/cli.js test tests/e2e/sounds.spec.ts --grep "live-alert priority feedback clears"
node node_modules/@playwright/test/cli.js test tests/e2e/sounds.spec.ts --grep-invert "live-alert priority feedback clears"
npm run lint
npm run typecheck
```

The two new and seven existing sound scenarios passed across the two post-fix runs. The full application browser suite and physical-device checks were not rerun for this presentation-only fix. Existing WARN/ERROR logging is unchanged, following the user's minimal logging preference; no routine UI logs or new environment flags were added.

## Prevention

- Tie feedback about an external operation to its identity and current lifecycle state, rather than retaining its text independently.
- Check feedback after natural completion, explicit cancellation, and replacement, as well as immediately after rejection.
- Assert that clearing feedback preserves timing state and allows the user to retry the intended action.
- Useful additional coverage: blocked previews during planning alerts and mocked native player cancellation/status callbacks.
