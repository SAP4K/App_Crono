# Preserve timer completion through focus changes and audio recovery

**Date:** 2026-11-05 00:37 UTC
**Files:** `src/app/timer.tsx`, `src/context/CronoContext.tsx`, `tests/e2e/timer.spec.ts`
**Severity:** medium

## Problem

- After a timer completed, focusing a duration field without editing it and opening Settings cleared the completed state and stopped its sound.
- If playback failed, a successful short run started immediately afterward still displayed `Timpul a expirat. Sunetul nu este disponibil acum.`

## Root Cause

The duration field's blur handler configured the timer even when its parsed duration was unchanged. Configuring a completed timer resets its state and run identity; the coordinator also stops audio before applying configuration. A focus event was therefore treated as a user edit.

The completion banner reused the provider's shared notice. Ordinary completion messages deliberately left that notice unchanged, so an earlier audio warning could survive into another run within the notice's 3.5-second timeout.

## Solution

Configure the duration on blur only when a valid, editable value differs from the saved duration. This preserves completed state and audio on an unchanged blur while retaining reset behavior for an actual duration edit.

Use a functional notice update on ordinary completion to clear a previous timer warning while preserving unrelated notices. A playback failure from the current run can still publish its existing warning.

Add two browser regression scenarios for unchanged focus followed by Settings, and failed playback followed by successful completion before the old warning expires. The first scenario also verifies that an actual duration edit still resets the completed timer.

Regression command, executed with Windows Node.js 24 from WSL:

```bash
node node_modules/@playwright/test/cli.js test tests/e2e/timer.spec.ts --grep "completed timer survives|successful timer completion clears"
```

Both scenarios failed at the expected assertions before the source changes and passed afterward. Related validation passed: 31 unit tests, lint, and typecheck. The full browser run passed 21 scenarios; its long stopwatch scenario exceeded the 45-second test limit, then passed alone in 35.2 seconds using `npm run test:e2e -- --last-failed --timeout=90000`. All 22 browser scenarios therefore passed across the run and rerun, without changing the configured timeout or assertions.

Existing warning/error logging remains unchanged, following the user's minimal logging preference. No routine input or success logs were added. Native keyboard and audio behavior was not tested on a physical device.

## Prevention

- Distinguish a field losing focus from a meaningful configuration change. Check both persisted state and side effects when an operation appears to be a no-op.
- Clear obsolete completion feedback at the next completion boundary without replacing unrelated notices.
- Exercise consecutive runs with a controlled clock and a recoverable media failure before the previous notice times out.
- Useful additional coverage: an unrelated session-save toast overlapping timer completion, plus keyboard focus and audio recovery checks on a physical phone.
