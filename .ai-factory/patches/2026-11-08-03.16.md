# Android startup crash from unavailable plural rules

**Date:** 2026-11-08 03:16 Europe/Bucharest
**Files:** `src/i18n/plurals.ts`, `tests/i18n.test.ts`, `package.json`, `package-lock.json`
**Severity:** high

## Problem

The installed Android release closed before displaying the application. AndroidRuntime reported `TypeError: undefined cannot be used as a constructor` during catalog imports.

## Root Cause

The translation module constructed `Intl.PluralRules` for every language at module evaluation. That constructor is unavailable in this Android Hermes runtime. Node and Chrome provide it, so previous browser, typecheck and export checks did not exercise the missing runtime capability. The release source map identified `src/i18n/plurals.ts:4` as the failing expression.

## Solution

Use named `make-plural/cardinals` imports for the six supported languages, with an exhaustive `AppLanguage` selector map. Install the pinned pure-JavaScript dependency through Expo and commit its lock entry. Count phrases retain the existing catalog forms. Optional diagnostics use `[FIX:plural-rules]` behind `EXPO_PUBLIC_DEBUG_FIX=true`; normal execution stays quiet.

A registered regression imports all catalogs in an isolated process with `Intl.PluralRules` removed. It failed before the fix and passed afterward. A second check compares all six cardinal selectors with Node Intl for counts 0–1000 and 1,000,000 (6,012 comparisons).

Validation: 139 Node tests, lint and typecheck passed. A signed Android APK was rebuilt, installed and launched on a physical Android 12 phone; the main screen rendered and its running process had no AndroidRuntime/ReactNative errors. The installed APK and the Downloads copy match SHA-256 `8f312a0d938243289a1f323c7e94a21507fca21b3c083b793446adf762d1c044`.

The existing browser server on port 8091 stalled during bundle loading before assertions. The unchanged language-selection scenario passed in 13.6 seconds on an isolated fresh server on port 8092, retaining the configured 45-second timeout. This does not establish why the older server stalled.

## Prevention

- Verify JavaScript runtime capabilities on an actual native build; successful exports and browser tests do not establish Hermes support.
- Keep the missing-capability regression in the registered Node suite and preserve independent plural-agreement assertions.
- Add the matching CLDR selector when extending `AppLanguage`; the exhaustive map makes omissions a type error.
- Useful additional coverage: switch all six languages in native Settings while a timer is active and check TalkBack count announcements.
