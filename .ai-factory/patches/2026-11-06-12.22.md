# Keep notification race verification in the registered regression suite

**Date:** 2026-11-06 12:22 UTC
**Files:** `tests/notificationCoordinator.test.ts`
**Severity:** low

## Problem

Verification found that task 11's registered tests did not permanently cover delayed native cancellation followed by same-run resume, delayed channel preparation while resetting/replacing runs, or replacement while a native registration result remained unresolved. Three temporary verification probes passed, but those probes were outside the repository and would not run under `npm test`.

No runtime notification defect was reproduced. The reported issue was missing durable regression coverage, rather than failing application behavior. Physical native acceptance and missing optional roadmap context are separate from this correction.

## Root Cause

Ad hoc verification evidence was treated as sufficient for closing the asynchronous coverage task without promoting each required scenario into the registered test file. The existing suite covered other delayed operations and failures, so its successful run did not reveal these missing cases.

## Solution

Add three deterministic tests to the already-registered `tests/notificationCoordinator.test.ts`, reusing its fixture and `deferred` helper:

- Hold cancellation of the old timer request, pause/resume the same run, and verify its changed deadline/physical ID while the independent schedule retains its existing request.
- Hold channel preparation while resetting the timer and confirming a schedule replacement; verify only the newest run/deadline is armed and obsolete physical IDs are cancelled.
- Persist an old native registration before holding its returned promise, replace the timer run, and verify late cleanup removes only the obsolete request while preserving the new registration.

Each test checks exact retained/cancelled IDs, expected deadlines, no mutation of application timing state, ready status and absence of warnings. Each has a one-second unit-test timeout to expose a coordinator that never reaches or completes an awaited boundary. Application source, native adapters, configuration, dependencies, context artifacts and the feature plan remain unchanged.

A temporary coverage-presence check first failed with the three missing scenario names. After the additions, the exact same check passed and confirmed the containing file remains registered in `package.json`. This static check reproduces the coverage omission; it is not a claim that application behavior failed before this test-only fix. It was not added as a permanent implementation-mirroring test.

Commands executed from the project root using Windows Node/npm from WSL:

```text
node --test tests/notificationCoordinator.test.ts
npm test
npm run lint
npm run typecheck
```

Results: all 21 coordinator tests and all 92 registered Node tests passed; lint, typecheck and whitespace checks passed. Hash comparisons confirmed all protected application/config/context files match the pre-fix baseline. The source-derived command catalog remained `1d2b8bcb5323d6a6dfc0db6f568ede5b74a603741688454017e6fdf7188fff8b`.

Browser tests, exports and SDK diagnostics were not repeated for this test-only change. The preceding verification passed 104 browser scenarios, Android/iOS/web exports and 21 Expo Doctor checks on the unchanged application. Physical Android/iOS Home/lock delivery, sounds, permissions and taps remain pending; these Node tests do not establish native delivery.

Runtime WARN/ERROR logging remains unchanged, respecting the user's minimal logging preference. `[FIX:notification-races]` command diagnostics record the coverage check; Node's named-test results and assertion diagnostics provide test feedback. No routine application logs or debug environment flags were added.

## Prevention

- Map required asynchronous scenarios to tests that actually run in the repository's configured command before marking coverage complete.
- Promote useful temporary probes into the registered suite; do not count external scripts as permanent regression coverage.
- Hold native promises explicitly instead of relying on wall-clock sleeps, and assert owner isolation, current deadlines, physical request identity and unchanged domain state.
- Model native persistence before a promise settles as well as a call that has not yet persisted.
- Keep test evidence separate from rebuilt-binary/device acceptance, and retain unrelated local changes.
- Useful additional coverage: cancellation failure during rapid schedule replacement, followed by an explicit retry that preserves the independent timer.
