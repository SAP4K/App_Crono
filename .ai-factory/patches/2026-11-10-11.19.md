## Problem

Verification of unified window scrolling found only four of eight plan tasks complete. The whole schedule draft already shared a virtualized list and its subpanels had bounded body scrollers, but the planned shared-window spec was absent and the documentation omitted the new editor interaction. The title/Close question Q1 remained unanswered.

The subsequent fix request refers to those verification findings. It does not answer Q1. This patch completes the independent coverage/documentation correction only; it does not claim the feature plan is complete or resolve the heading policy.

## Root Cause

A required decision about modal headings blocked final shared-window acceptance. Independent checks of body movement, action reachability, draft preservation and file transfer were left pending with that decision, although their expected behavior is common to both heading choices. Earlier editor-only passing evidence did not prove those additional window families.

## Solution

Register 17 behavioral browser cases through the existing Playwright discovery:

- All seven Settings sections in six languages and both themes, using compact widths and enlarged text. Check simultaneous group movement, body ownership, final-control reachability, background accessibility isolation, Escape/Back focus and unchanged preferences/audio.
- A real 1,000-lap session: summary/lap movement, final lap and Share/Delete reachability, and cancellation without deletion.
- Real file chooser/upload/import review in a short window, with reviewed confirmation, unchanged clocks/preferences and reload persistence.
- Short date chooser, calendar and repeat panels, and an overflowing reset confirmation, preserving staged changes and explicit acceptance/cancellation.

The pre-change existence probe reported `tests/e2e/sheetScrolling.spec.ts: absent`; the same probe now reports `present`. This establishes a durable coverage omission, not a production behavior failure. No application code needed changing during this correction. An initial 14-case run passed 13 cases; the English Light About case exposed a test helper that sent its only wheel gesture before enlarged layout finished measuring. The helper now issues another real wheel gesture when the observed endpoint remains unreached, retaining its one-pixel assertion and existing timeout. All 17 final cases pass together.

Use the docs checkpoint to describe one complete editor list, independent duration inputs, explicit Save and source restoration. Qualify exact position restoration by unchanged layout. Update the factual active-plan pointer while retaining Q1 and physical acceptance as pending. No requirements were rewritten; 37 relative file links resolve. Keep the existing documentation structure and historical evidence.

## Prevention

- Separate body-scroll invariants from independent heading-policy assertions, so unresolved design choices do not prevent useful authorized acceptance work.
- Keep required choices pending; a subsequent skill invocation is not an answer.
- Register representative maximum-size and real-transfer journeys instead of relying on static wrappers or editor-only evidence.
- Compare simultaneous positions in one layout frame. When layout can remeasure, retry actual gestures against the current endpoint rather than weakening assertions or assigning scroll offsets directly.
- Distinguish a test-helper failure from an application failure, and preserve complete run/rerun evidence.
- Additional coverage after the heading choice: assert that exact policy for Settings, history details, confirmations and every editor panel. Physical Android/iOS touch, keyboard avoidance, font scaling and TalkBack/VoiceOver checks remain recommended and pending under the user's device-test deferral.
