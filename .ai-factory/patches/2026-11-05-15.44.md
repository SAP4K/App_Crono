# Avoid compressed local bundles exhausting browser test deadlines

**Date:** 2026-11-05 15:44 UTC
**Files:** `playwright.config.ts`, `README.md`, `.ai-factory/DESCRIPTION.md`
**Severity:** low

## Problem

The full browser verification passed 55/56 scenarios. The unchanged stopwatch journey exceeded its configured 45-second limit; a separate 90-second diagnostic also timed out. Documentation still described earlier successful runs without recording this newer failure.

## Root Cause

The journey loads the app and reloads it three times to check real persistence. Traces showed roughly 20–23 seconds per navigation/reload in the diagnostic, dominated by compressed development-bundle delivery. A direct probe of the same 4,472,890-byte bundle with different `Accept-Encoding` values took 16 ms to read the identity response body, versus 8,517 ms for gzip and 8,200 ms for Brotli on this host. The precise source of the host's compression delay was not isolated.

Expo's installed Metro middleware compresses `.bundle` and `.map` responses. Repeated compressed loads consumed the functional test's overall budget. This was a local test transport issue; there was no evidence of a stopwatch, persistence, or palette defect.

## Solution

Set Playwright's `extraHTTPHeaders` to request `Accept-Encoding: identity` from the configured loopback development server. All functional assertions, four page loads, test limits, retries, device settings, and application code remain unchanged. The browser still fetches and executes the real Metro bundle and assets; no network responses or application state are mocked by this fix. The header configuration follows the [Playwright request-header option](https://playwright.dev/docs/api/class-testoptions#test-options-extra-http-headers).

Regression command, executed with Windows Node.js 24 from WSL:

```bash
node node_modules/@playwright/test/cli.js test tests/e2e/crono.spec.ts --grep "stopwatch, laps"
```

Before the configuration change, this command failed after 45.7 seconds during `page.reload()`. The exact same command passed afterward in 23.2 seconds. A subsequent `npm run test:e2e` passed all 56 scenarios in one run (7.6 minutes), including the unchanged stopwatch journey in 21.7 seconds, with default 45-second limits and no retries. Lint, typecheck, all 51 Node tests, and diff checks passed. All-platform export had already passed for this application code and was not repeated for the test-only configuration change.

Update README and DESCRIPTION with the latest complete result and the resolved timeout. Existing application WARN/ERROR logging is unchanged, following the user's minimal-logging preference; Playwright retains its normal failure diagnostics. No routine runtime or success logs were added. Physical-device checks remain pending.

## Prevention

- Separate page-load and bundle-transfer time from UI assertions when diagnosing a global test timeout.
- Compare compressed and uncompressed delivery before increasing deadlines, splitting a useful persistence journey, or changing application timing logic.
- Rerun the unchanged failing check first, then the full browser suite when changing shared browser configuration.
- Keep verification notes tied to the latest complete run and distinguish historical passes, diagnostics, and unresolved failures.
- Useful additional coverage: a cold-start persistence journey against a production web export with normal browser compression negotiation. Local uncompressed functional checks do not establish production compression performance or native-device behavior.
