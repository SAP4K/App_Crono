# Preserve browser timer cancellation context in shared hooks

**Date:** 2026-11-05 19:04 Europe/Bucharest
**Files:** `src/hooks/useAlertPlayback.ts`, `src/hooks/useTimerCompletion.ts`, `src/hooks/usePlanningRunner.ts`, `tests/e2e/realTimers.spec.ts`, `README.md`
**Severity:** medium

## Problem

The user received `TypeError: Illegal invocation` at `alertPlayback.ts:41` during audio handling. Verification reproduced the same exception during sound preview, countdown pause, and schedule pause in Chrome with native browser timers. The previous 56-case browser suite passed because the affected suites replaced browser timers with fake clocks.

## Root Cause

All three runtime hooks injected `cancel: clearTimeout`. Their framework-free controllers call `a.cancel(handle)`, which gives the browser function the adapter object as its receiver. Chrome rejects that receiver. Cancellation failure also breaks the audio failure handler when it calls `invalidate()`, so a recoverable playback problem becomes an unhandled exception.

A direct Chrome control reproduced the difference: the bare adapter call threw with native timers, an arrow wrapper succeeded, and the invalid bare call succeeded after installing Playwright's fake clock. Node/controller stubs and deterministic clocks did not exercise this browser API requirement.

## Solution

Replace the cancellation adapter in each hook with `cancel: (handle) => clearTimeout(handle)`. Keep the pure controllers, transports, persistence, priorities, startup/duration limits, and cross-platform handle types unchanged. No browser-only `window` dependency or new package is needed. Consulted the installed [Expo SDK 57 reference](https://docs.expo.dev/versions/v57.0.0/), Expo's documentation index, and [React Native 0.86 timer documentation](https://reactnative.dev/docs/0.86/timers) before changing the runtime adapters.

Add four browser regressions without replacing timer functions:
- Actual preview playback, theme change, natural five-second expiry, and explicit Stop.
- A failed media load, visible recovery feedback, successful retry, and Stop without uncaught errors.
- Countdown pause/resume, stable run identity, confirmed reset, and independent state preservation.
- Schedule pause/resume/reset, stable run identity, retained template, and independent clocks.

The preview tests observe real Audio instances without replacing native play/pause methods. They serve the unchanged bundled Classic WAV bytes directly and explicitly abort the failed-load request. An initial unrouted test hit the existing four-second startup guard while Metro's media request was still pending; this was handled fallback after the cancellation fix, rather than the original unhandled exception. The byte fixture isolates native timer/media behavior from that local transport delay. Existing server-fetch/PCM-decoding checks remain. Production asset-transfer performance and audible phone behavior are separate evidence.

Final regression command, executed with Windows Node.js 24 from WSL:

```bash
npm run test:e2e -- tests/e2e/realTimers.spec.ts
```

All four final regressions failed before the adapter fix with `Illegal invocation`. The exact same test file and command passed afterward (4/4, 42.4 seconds total). Earlier three-case checks also reproduced the original exception; after isolating asset delivery and adding failure recovery, the final four-case suite was rerun against the unfixed adapters before verifying the fix. No assertion was weakened to accept the exception.

Related validation passed: lint, typecheck, all 51 Node tests, fresh Android/iOS/web exports, and all 60 browser scenarios in a single full run (10.5 minutes), retaining the 45-second test limit and no retries. README's current validation notes were refreshed. Context artifacts and the unapproved improve-plan proposal were not changed. Physical-device and signed-build checks remain pending.

Existing WARN/ERROR logging is unchanged, following the user's minimal-logging preference. No routine input/success logging or new debug environment flags were added; normal test traces and page-error assertions provide diagnostics.

## Prevention

- Wrap browser/platform functions when injecting callbacks if their receiver matters; do not assume that assigning a global function to an object preserves its calling context.
- Keep at least one real-browser-timer integration path alongside deterministic clock tests.
- Exercise both successful playback and recovery, because cleanup errors can turn handled failures into unhandled exceptions.
- Isolate transport latency explicitly in functional fixtures and preserve separate checks of the actual served assets.
- Require the exact final regression to fail before the source fix and pass afterward; rerun the full suite after shared adapter changes.
- Useful additional coverage: real-browser background/unmount cancellation and physical iOS/Android checks of pause, Stop, audio routing, and app return.
