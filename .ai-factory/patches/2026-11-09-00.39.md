# Keep native completion cleanup independent and invalidate resumed deadlines

**Date:** 2026-11-09 00:39 EET
**Files:** `src/core/completionAlerts.ts`, `src/hooks/nativeAlertPlayback.ts`, `modules/crono-completion-alerts/android/src/main/java/ro/appcrono/alerts/CompletionAlertPolicy.kt`, `modules/crono-completion-alerts/android/src/main/java/ro/appcrono/alerts/CompletionPlaybackBroker.kt`, `modules/crono-completion-alerts/android/src/test/java/ro/appcrono/alerts/CompletionPolicyTest.kt`, `modules/crono-completion-alerts/android/src/test/java/ro/appcrono/alerts/CompletionBrokerTest.kt`, `tests/completionAlerts.test.ts`, `tests/completionNotificationAdapter.test.ts`, `tests/nativeAlertPlayback.test.ts`
**Severity:** high

## Problem

Verification of one-minute Android alerts reproduced two blocking failures. A ledger write exception escaped the real native completion callback before foreground-service cleanup and state publication. Separately, a paused and resumed timer could leave its original native deadline eligible while OS inventory reconciliation was waiting: the original deadline was 11000, pause occurred at 2000, and resume at 5000 moved the valid deadline to 14000.

The user requested these fixes after verification and explicitly deferred physical device tests. No device installation, permission change or phone test was attempted during this fix.

## Root Cause

`CompletionPlaybackBroker.stop()` released playback resources but then performed persistence, service finishing and publication in one unguarded sequence. A storage failure prevented later independent cleanup work and propagated out of the Handler callback. Failure cleanup and replacement-service cleanup had the same sequencing risk.

The native policy identified timer/planning owners only by run ID and paused state. Resume intentionally preserves a run ID while changing its deadline. The JavaScript policy writer also rebuilt policy only after an asynchronous native acknowledgement, coalescing an accepted pause/resume into the same original running policy. Native invalidation therefore depended on later inventory reconciliation even though the accepted application state already made the old deadline obsolete.

Adding strict boundary matching alone would interrupt valid sounds when a schedule advanced or completed, or when a completed run was hydrated while its native alert was still playing. Boundary identity must survive natural completion while being revoked by pause, reset, replacement or changed deadlines.

## Solution

Run persistence, foreground-service finishing and publication as separate guarded cleanup steps after releasing resources and clearing in-memory playback state. Each failure emits an existing deduplicated warning with a bounded `[FIX:completion-cleanup]` operation label, then allows remaining cleanup to proceed. Apply the same independence to failure and replacement-service cleanup. Logging remains warnings/errors only and excludes saved user data.

Extend the pure completion policy with accepted event IDs and exact deadlines, plus completion flags. Capture every accepted snapshot synchronously before awaiting native acknowledgement; serialize delivery of the latest captured policy. Native eligibility now requires an exact event/deadline match when the extended projection is present. A resumed timer therefore invalidates 11000 and accepts 14000 even while notification inventory is blocked.

Project the complete cumulative schedule timeline so advancing an action preserves an already ringing boundary. Retain the accepted timeline through natural completion. On cold attachment to the same completed run, native policy resolution can preserve its previously validated timeline. Pause, reset and replacement do not inherit it. Validate bounded, unique, owner-scoped projections; legacy native ledgers without a projection retain their trusted registrations until successful hydration supplies the new policy. The AppData schema, persistence key, package identity, permissions, dependencies and sound assets are unchanged by this fix.

Permanent regression coverage is registered in the existing Node and native test commands. It exercises the actual native completion callback with an injected storage write failure, exact native deadline eligibility, coalesced accepted updates behind a native acknowledgement, and the composed notification adapter while inventory is blocked. Controls cover timer reset, schedule advancement/completion, shifted schedule deadlines and completed-run reattachment.

## Prevention

- Keep resource release, persistence, service shutdown and observer publication independently guarded when any can fail. Test an exception in an early step and verify later steps still execute through the actual production callback.
- Treat an event ID and its accepted deadline as a boundary identity. A stable run ID alone cannot distinguish deadlines before and after pause/resume.
- Capture meaningful accepted transitions before asynchronous coalescing. Do not defer invalidation to inventory reads or reconstruct history from only the final snapshot.
- Preserve valid current playback through natural action advancement, completion and hydration while explicitly revoking obsolete identities on cancellation and resume.
- Test the composed adapter with held asynchronous boundaries as well as pure policy functions. Retain positive controls so stricter validation does not silently suppress legitimate alerts.
- Additional coverage when physical testing resumes: pause/resume around the old deadline while switching Home/lock states, plus one-minute acoustic duration, Stop and natural service shutdown on the Redmi. Keep this pending until device testing is authorized again.
